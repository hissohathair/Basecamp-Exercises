# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A Basecamp build-along exercise: a multi-tool support ticket agent for "TechFlow" that uses the Claude API directly (no framework). The learner fills in `TODO` stubs to build up an agentic loop in stages — tool schemas → basic loop → structured output → adaptive thinking → streaming.

Model: `claude-sonnet-4-6`. SDK: `anthropic` (installed in-notebook via `%pip install`).

## Files

- `Developer_Platform.ipynb` — **the exercise**, runs in Jupyter/Colab/VS Code. This is the source of truth.
- `Developer_Platform.py` — a flat mirror of the notebook's cells concatenated. Useful for grep/reading the full exercise in one shot, but **not executable as a script** (contains `%pip` magic, expects an IPython environment). Do not edit this file expecting changes to propagate to the notebook; edit the `.ipynb` instead.
- `README.md` — learner-facing run instructions (Codespaces / VS Code / local Jupyter).
- `.venv/` — local Python virtualenv (gitignored target; do not commit).

## How to run

The notebook is the entry point. There is no test suite, lint config, or build step in this folder — the exercise is run cell-by-cell in a notebook UI. To validate changes, run the notebook end-to-end (the final cell exercises streaming + thinking + tools + structured output against `TKT-1045`).

`ANTHROPIC_API_KEY` must be set via env var, Colab Secrets, or pasted into the setup cell. The setup cell does a pre-flight `messages.create` ping and prints `🚀 Ready to build!` on success.

## Agent loop architecture — non-obvious patterns

The exercise teaches a specific shape of agentic loop. When helping a learner complete the TODOs, preserve these invariants:

- **Pass back ALL content blocks** from the assistant turn (including `thinking` blocks) when appending tool results. Dropping thinking blocks breaks subsequent turns when `thinking={"type": "adaptive"}` is in use.
- **Tool loop and structured output are separate calls.** `output_config={"format": RESOLUTION_SCHEMA}` constrains all text output and is incompatible with tool use. The pattern is: run the tool loop with no `format`, then make one final call with `tool_choice={"type": "none"}` + the format constraint, appending a user message like "Provide your structured resolution as JSON."
- **`get_structured_result()` reads the *last* text block**, not the first. With adaptive thinking, content is typically `[thinking, text]` — the JSON is in the trailing text block.
- **Effort control** flows through `output_config={"effort": effort}` (e.g. `"high"` / `"low"`), used alongside `thinking={"type": "adaptive"}`. The final structured call carries both `effort` and `format` in `output_config`.
- **Streaming variant** uses `client.messages.stream(...)` as a context manager and `stream.get_final_message()` to get the assembled response for the next loop iteration. Event types to handle: `content_block_start` (branch on `content_block.type` — thinking/tool_use/text), `content_block_delta` (handle `thinking_delta`, `text_delta`, `input_json_delta`).

## Tool surface

Three mock tools defined in the setup cell, dispatched through `TOOL_FUNCTIONS` / `execute_tool(name, input)`:

- `get_ticket(ticket_id)` — reads from in-memory `TICKETS` dict.
- `search_kb(query)` — naive word-overlap search over `KB_ARTICLES`, caps at 3 results, falls back to `KB-000` "escalate to Tier 2" stub.
- `resolve_ticket(ticket_id, resolution, status)` — `status` must be one of `resolved` / `escalated` / `pending_customer` (encode this as an enum in the tool schema).

Tickets and KB articles are intentionally crafted to exercise specific paths — e.g. `TKT-1046` is the ambiguous one used to compare `effort="high"` vs `effort="low"` thinking traces; `TKT-1045` is the streaming demo finale.

## Conventions

- The notebook uses `claude-sonnet-4-6` and a 900s client timeout (needed for `max_tokens > 21333` on non-streaming calls). Keep these unless the user asks otherwise.
- `max_tokens=32000` is used for the agent calls.
- The `SYSTEM_PROMPT` encodes TechFlow product tiers, SLAs, and escalation criteria — don't trim it when refactoring; the exercise relies on the model having that context.
